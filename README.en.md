# PoL2 Governance Compiler

[中文](README.md)

A knowledge-and-gates-only toolbox for [NaturalDAO PoL-Governance](https://github.com/naturaldao/NaturalDAO/tree/main/PoL-Governance). A coding agent uses it to compile a PoL2 runtime governance layer for one concrete host (for example a DSH plugin), while ten immutable gates stop it from passing the evaluation through shortcuts such as blocking everything, reading the test set or hiding failed requests.

The approach borrows from [MetaInfer](https://github.com/HuangPuStar/MetaInfer): MetaInfer generates a dedicated inference engine per (model × hardware × workload); this project compiles a dedicated governance layer per (host × decision surface × clause subset × latency budget).

> **Status: v0.2.0, phase 0 complete.** All ten gates exist, with three constant degenerate policies and a red-team matrix of 16 cheats; 56 tests. No judge model is connected and there is **no claim about model quality**.

![Architecture](docs/figures/fig1_architecture.png)

*Figure 1. Knowledge (clause contracts, the DATA-02 ontology, the rulings queue) is reused and grows. Three isolated roles form the compile loop; any failing gate sends the work back to the compiler. Clause ambiguities go to the rulings queue for the team to decide; agents do not invent rules. The degenerate floor always runs beside the candidate through G06.*

## The ten gates

| Gate | Source rule | Shortcut it blocks |
|---|---|---|
| G01 schema and execution state | PROTOCOL machine interface | hiding wrong verdicts behind timeouts; dropping hard cases |
| G02 splits never cross a family | SPEC phase 1 | rewriting test items into the tuning split |
| G03 duplicates and length shortcut | SPEC quality checks | near-duplicates; labels guessable from text length |
| G04 no holdout in the tree | AGENTS data boundary | putting the holdout in the repository |
| G05 threshold provenance | SPEC phases 1 and 3 | choosing thresholds on the test split |
| G06 degenerate floor | PROTOCOL comparisons | allow-all, block-all, clarify-all, or random mixtures |
| G07 lineage isolation | SPEC teacher generation | judging with the family that wrote or labelled the data |
| G08 clause coverage, three classes | SPEC phase 1 | claiming a clause without its hard cases |
| G09 honesty statements | SPEC, PROTOCOL | calling a seen public test blind; ranking on unreviewed labels |
| G10 latency and failure disclosure | PROTOCOL | omitting failed requests; understating p95 |

## Why G06 uses the convex hull

![G06 floor](docs/figures/fig2_floor.png)

*Figure 3. Over-block rate against miss rate on the synthetic fixture (48 violating, 48 normal). A label-blind coin flip between allow-all and block-all lands anywhere on the dashed line J = 0 (grey: 1000 seeds). A candidate must lie below it, and the one-sided 95% lower bound of J must be positive. The honest candidate has J = 0.88, lower bound 0.75. A coin flip still passes about 5% of the time (5.2% on the fixture, 4.4% on the pilot): the known cost of a 95% level.*

## Quick start

Python 3.10+; the gates need no third-party packages. Redrawing figures needs matplotlib.

```powershell
python -m unittest discover -s tests -t .
python -m redteam
python -m baselines.constant --policy always_block --inputs data/pilot/pilot.jsonl --out build/always_block.jsonl
python -m gates.run_all --cases data/pilot/pilot.jsonl --predictions build/always_block.jsonl
python -m tools.make_figures
```

The fourth command exits with code 1 by design: G06 rules always_block not above the floor, and G08 fails because only 2 of the 20 pilot cases are "insufficient". The pilot is assistant-written and unreviewed; it exercises interfaces and must not be used for ranking.
