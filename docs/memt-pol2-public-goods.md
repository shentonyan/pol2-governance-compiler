# MEMT-1.0 与 PoL2 公共品时代：技术借鉴、治理边界与验证路线

**审阅日期：** 2026-10-29

**论文版本：** arXiv:2610.26825v2（2026-10-20）
**项目：** [MemT-1.0 官方仓库](https://github.com/MemTensor/MemT-1.0) · [模型集合](https://huggingface.co/collections/MemTensor/memt-1) · [论文 HTML](https://arxiv.org/html/2610.26825v2)

## 结论先行

MEMT-1.0 对 PoL2 具身治理最有价值的启发，不是让机器人“把规则记住”，而是让治理系统能持续积累跨轮经验，同时把**经验记忆、规范权威、行动授权和可审计记录分成不同层**。它展示了可学习的持久记忆状态和经验复用的工程路径；论文没有研究公共资源分配、共同体授权、政策合法性、撤权后的物理恢复或机器人安全。

对“PoL2 公共品时代”，可提出的研究命题是：**具身代理能否在记住经核验的历史事实、执行经验和纠错记录的同时，按可审计的 PoL2 合约为共享资源提供服务，并在授权撤回、资源冲突和规则更新时保持公平、可追溯和可恢复？** 这比单独测“记忆准确率”或“违规动作拦截率”更接近公共品治理问题。

建议借鉴 MEMT 的两项系统设计：轨迹隔离的状态记忆，以及将记忆存储与记忆读取分开的流程。不要把潜在记忆状态当成授权凭证、规则版本、申诉结果或公共记录；这些应由版本化、可检查、可撤销的治理账本及确定性执行门处理。该区分是本报告提出的设计原则，不是 MEMT 论文的实验结论。

## 1. MEMT-1.0 项目与论文讲了什么

### 1.1 论文定位与项目材料

论文由 MemTensor Team 发布，标题为 *MemT-1.0: Towards Memory-Native Evolution*，属于 arXiv 预印本，v1 提交于 2026-10-19，v2 于 2026-10-20 修订。项目仓库提供推理代码、使用说明和模型链接。仓库说明将论文材料标为 CC BY-NC-SA 4.0，将仓库软件标为 PolyForm Noncommercial 1.0.0；模型权重、数据集及部分第三方材料可能另有许可。若仅在本仓库讨论或复现实验设计，应链接原项目，不复制其代码、论文段落、权重或数据；实际部署前须逐项确认所用权重和依赖的许可。

### 1.2 架构：在线动态记忆加离线训练的记忆能力

MemT 把一个 native memory block 接入选定的 Transformer 层，在原模型注意力旁并行执行 memory attention，再把两路结果合入模型计算。它包含：

- **动态本地记忆（local memory）：** 每条交互轨迹拥有自己的矩阵状态；新轨迹从空状态开始，交互时在线更新。
- **可训练的超记忆（hyper memory）：** 查询、键、值投影，以及擦除、写入、遗忘和读出门。此处的参数通过训练获得，线上交互时固定。
- **存储与利用两个程序：** 存储程序从本轮隐状态中写入信息；利用程序在后续生成中读取记忆。论文以 Gated DeltaNet-2（GDN-2）的 token 级更新替换较早的 token 选择式写入，并引入 Mixture-of-Storage（MoS）扩展记忆容量。MoS 对多个记忆专家使用密集路由，写入路由与读取路由分开学习，但共享专家地址。

所以“模型会演化”需要准确解释：**交互期间主要变化的是轨迹级动态记忆状态；模型的骨干权重及训练得到的超记忆参数不会因每次线上对话自动改变。** 论文把跨任务的自主经验获取和持续记忆巩固列为后续方向，并没有把它作为本版已经完成的能力。

论文发布两个模型：MemT-1.0-Nano（36B 总参数、3B 激活参数、约 10M 动态记忆参数）和 MemT-1.0-Flash（288B 总参数、17B 激活参数、约 336M 动态记忆参数）。项目 README 提供基于 SGLang 的服务和 Python 客户端示例；其部署示例依赖多 GPU 服务器，不能把“固定记忆状态”误解为低算力或端侧可直接运行。

### 1.3 训练和评估

论文报告 34B token 训练语料，其中约 20B 用于 continued pre-training，约 14B 用于后训练；Nano 以 Qwen3.6-35B-A3B 为骨干，Flash 使用进一步后训练的 DeepSeek-V4-Flash 骨干。记忆能力在 11 个基准上评估，覆盖长历史信息保留与检索、动态更新、操作和个性化；另以 6 个通用能力基准检查增加 native memory 后的能力保持。

作者报告模型平均超过所测参数式记忆基线，并在整体上与检索增强的文本记忆有竞争力；项目 README 也明确指出，强文本记忆系统整体仍领先，尤其是在长历史中需要精细证据检索的任务。128K 历史长度下，Nano 相对 full-context KV cache 报告约 1.86 倍端到端推理加速和约 66 倍持久存储降低。效率测试使用特定 HF 推理配置、35 段历史、固定 512-token 查询和强制生成 128-token 答复；数字不应直接外推到其他模型、机器人硬件或服务负载。

代理任务实验把从成功编码轨迹提炼的程序性经验写入 native memory，再测试代码代理能否在任务文本中不保留该经验的情况下复用它。论文报告 SWE-bench Verified 与 Multilingual 上的成功率或重复运行一致性改善；例如 Multilingual 的 Before Execution 设置平均成功率从 60.00% 到 62.89%，pass^3 从 45.33% 到 53.67%。Harness-Triggered 设置报告 63.56%，略高于文中固定 rank-1 文本经验的 63.00%。这说明在其数据、代码任务和执行框架内，内化程序性经验可能帮助代理复用经验；它不说明机器人政策选择、规范遵循或公共资源分配会同样改善。

### 1.4 作者承认的限制及外部审阅边界

固定容量把随历史长度增长的记忆压到常数级状态，因而会损失细节；作者指出旧信息保留与新信息写入存在取舍，精确回忆仍有挑战。作者还把本地记忆与训练得到的超记忆如何相互巩固列为待研究问题。项目仓库将代码、论文、权重和第三方组件分开许可，不能仅凭仓库公开就假定模型和全部数据可自由再发布或商用。

此外，本文是预印本报告；目前结果应表述为作者报告的实验结果。所检视的任务主要是语言模型记忆基准与代码代理，并没有具身机器人、真实共同体、公共品服务、政策争议、撤权恢复或第三方损害评估。除上述明示限制外，下文关于记忆投毒、策略陈旧、跨主体隐私和共享记忆权力集中等内容，是对 PoL2 使用场景的风险分析，不是该论文已经验证的缺陷。

## 2. 它与 PoL2 具身工作的关系

本次审阅的 NaturalDAO 本地工作树将已有研究分为两条线：一条检验提示、候选集和训练是否改变动作选择；另一条检验确定性门控、授权撤回和恢复状态。材料明确指出，当前结果不能证明通用机器人推理的总体 PoL2 净收益，也不能推出真实机器人安全性。此前实验主要是受限合成任务和 Panda/MuJoCo 仿真，动作门能阻止特定未授权动作；撤权实验显示“阻止后续任务”与“把仍被夹持的物体安全放回”是不同问题。

MEMT 能补足的是**经验跨轮保留与任务过程复用**这一系统层问题。它不能替代 PoL2 的规范映射、治理条款裁定、机器可判定合约或动作执行门。建议将其映射为以下分层：

| 层 | 角色 | MEMT 可提供的帮助 | 不应赋予它的权力 |
|---|---|---|---|
| 观察与经验 | 记录经过核验的环境状态、失败模式、维修与服务历史 | 将相关经验压缩并在后续任务读取 | 把一次代理生成的记忆提升为事实或公共记录 |
| 规范与授权 | 版本化 PoL2 条款、适用范围、授权主体、有效期、撤回状态 | 依据明确版本与案件背景辅助检索、解释 | 由隐式记忆决定谁有权、规则是什么、授权是否仍有效 |
| 执行与恢复 | 确定性策略门、设备适配器、独立恢复状态机 | 记住操作经验以减少重复错误 | 让生成模型或潜在记忆直接绕过门控或延长权限 |
| 公共问责 | 可检查的事件、版本、理由、申诉/复核和修订记录 | 在访问控制下检索相关先例 | 用无法逐条追溯的潜在状态取代共同体记录 |

这里的关键分离是**记得一项规则**不等于**该规则经谁授权**；**记得某次授权**不等于**授权此刻仍有效**；**过去执行成功**不等于**当前资源分配公平或可接受**。授权应在线从当前版本的显式治理状态计算，不应依赖模型记忆中的印象。

## 3. 从具身动作门转向 PoL2 公共品治理

“公共品时代”如果要成为研究问题，核心不能停在单个代理是否执行正确动作。至少要问：机器人系统生产何种公共利益、谁能使用、有限资源如何分配、受影响者如何异议或修订、错误如何纠正，以及长期运营成本由谁承担。

还要区分公共品和共同资源。公共品通常以非排他、非竞争为特征；共同资源则常有较高排他难度和较强消费可减性（一个人的使用会减少他人可用量）。机器人服务可提供非排他性公共收益，但机器人时间、能源、电池、算力、通行空间与物资库存通常是有限且相互竞争的共同资源。把有限资源直接叫作“公共品”会掩盖过度使用、拥堵、排斥和维护成本。[Ostrom 对共同资源的界定](https://hdl.handle.net/10535/5733) 支持这一区分。2026 年的 AI commons 分类预印本把数据、算力、模型、知识/评估和能源作为 AI 栈中的共同治理资源层，并用制度功能分析其治理；UNDP 对数字公共基础设施的描述也强调包容、互操作和以公共利益为导向的治理。这些框架可借鉴为分析轴，但并不构成 PoL2 或具身系统的实证验证。

由此可把“PoL2 公共品时代”拆成两类研究对象：

1. **服务产出：** 可及、可靠、可负担的服务，例如应急物资递送、公共空间巡检、辅助设施维护。
2. **被共同使用的稀缺资源：** 机器人队列、电池/能源、算力、道路或场地时间、共享库存；其治理需要关于准入、优先级、限制、监测、纠错与维护的制度设计。

PoL2 第七章的人类公共福利治理条款在当前治理编译器的待裁定队列中仍是 N-01：是否把第七章条款登记进可执行本体、由谁登记，还没有团队裁定。故本报告提出公共福利方向的研究问题，不自行把它编译成规则，也不为某种“公平分配”公式作 PoL2 正统解释。

## 4. 值得吸收的设计点与不能照搬的部分

### 可借鉴

- **轨迹隔离。** MEMT 为独立轨迹维护不同动态状态。具身代理可据此把设备、任务、服务对象或治理会话的记忆边界显式化；不同主体的隐私和利益不能因为共享同一模型而混到一起。
- **存储与读取分离。** 不应把“代理观察到”直接等同于“记忆写入并可影响决策”。先验证事件来源和状态，再决定记录；检索时再按当前任务、权限和有效期筛选。
- **将程序性经验表示成带条件的经验。** MEMT 的编码经验包含触发条件、建议步骤、适用约束和验证程序。PoL2 机器人日志可沿用这一信息结构，但需增加来源、时间、观测置信度、条款/策略版本、审查状态和撤销状态。
- **持续测量记忆容量的边际效果。** MoS 的容量扩展提示，记忆容量是独立设计变量。治理实验应测增加历史跨度后，目标任务是否改善、旧证据是否被覆盖、错误经验是否持续影响决策、延迟和储存成本如何变化。
- **保留文本检索基线。** MEMT 与文本记忆表现并非在所有维度都占优。对规范与授权这类必须能给出来源的内容，显式版本化条款和可检索账本可能比仅靠潜在压缩状态更合适。

### 不能照搬为 PoL2 结论

- 记忆压缩或读取准确率不代表价值对齐、爱之证明、正当性或参与者授权。
- 代码任务的成功率改善不代表机器人任务安全、少数群体可及或公共资源分配公平。
- 每条轨迹的状态隔离不等于不同社区、机器人供应商、服务对象和公共机构之间的制度性隔离。
- 固定容量和高压缩率可能让错误历史、过期规则或少数人提出的需求被覆盖；论文没有评估这些治理损害。
- 把记忆状态设成“会随使用演化”不会自动产生可接受的规范演化程序。谁能提出、审查、批准、回滚和申诉，仍需明文制度与可核验记录。

## 5. 建议的 PoL2 研究任务

### 研究问题

在具身系统按社区目标提供共享服务、同时管理稀缺运行资源时，经过来源与时效审查的跨任务经验记忆，能否在不降低授权可追溯性和受影响者可及性的前提下，提高任务完成率、纠错能力和连续服务能力？

### 最小先导：共享配送机器人模拟

先在受控模拟中设一个仓储/校园配送代理：它使用有限电量、任务时间窗和库存，处理不同紧急程度的服务需求；部分需求冲突或信息不足，并可在任务进行中撤回授权。PoL2 规范到具体状态和动作的映射须先由团队冻结并审查；本体尚未覆盖的公共福利条款先保持显式“未裁定”，不混入主结果。

建议预注册一个 **2 × 2 因子设计**：

| 因子 | 条件 |
|---|---|
| 经验记忆 | 无跨任务经验 / 有跨任务经验（原型、文本检索或可用 MemT 后端） |
| 执行治理 | 沙盒门关闭 / 确定性策略门开启 |

主比较需把相同任务、同一初始状态、模型/提示、候选动作和算力预算配对；门关闭只在隔离模拟器中进行。最先用版本化文本/外部审计账本实现可控的 memory interface，验证“写入—读取—过期—纠错—撤回”语义；只有模型、许可和运行资源条件合适后，再把 MemT 接入作为一个记忆后端。这样先检验治理接口，不会把 MEMT 的大模型架构、提示、记忆机制和安全门一次性混成无法归因的总包。

### 结果指标

- **公共服务产出：** 需求满足率、按时交付率、延迟、库存浪费、连续服务时长。
- **可及与分配：** 按需求类型和预先定义的服务群体报告覆盖率、等待时间与拒绝率；报告最差群体指标和资源分布，而不只报总成功率。
- **治理门：** 未授权动作漏放、合法任务误拦、信息不足时澄清/等待、撤回生效延迟、策略版本与审计记录完整率。
- **撤权与恢复：** 撤权后是否停止原任务、是否造成不安全物理中间态、能否以独立恢复许可返回稳定状态、恢复失败和资源代价。
- **记忆质量：** 来源可追溯率、过期信息影响率、跨轨迹污染率、重要历史遗漏率、被纠正信息的清除/覆盖时延、错误经验在后续决策中的传播。
- **运行成本：** 端到端延迟、记忆读写开销、状态存储、能源/计算量、通信或服务故障后的降级行为。

主要统计单位应是**任务族/独立情景**，不能把同一场景中多个提示或门控条件当作独立样本。先用小规模先导估计变异和失败类别，再确定多场景正式实验的功效与停止规则。效果报告同时呈现门开与门关下的公共服务效用，避免“零违规”掩盖合法服务被全面阻断。

### 预先写明的失败条件

若总体服务完成率上升但最差群体的覆盖或等待时间明显恶化；若记忆中的旧授权影响当前执行；若共同体无法查明关键决定来自哪个事实或条款版本；若撤权只阻止投递但把货物/机器人留在危险状态；若记忆改善只来自更大的提示或额外计算，而无独立记忆贡献——这些结果都应写成对方案的限制或否证，不能以总体成功率抵消。

## 6. 对治理编译器当前路线的具体建议

1. **先解决语义边界，再做 memory backend。** `rulings/OPEN.md` 的 N-01 明确第七章是否纳入条款本体尚待团队决定。继续按仓库约定保持开放，不从“公共品”一词推导出单一分配规则。
2. **把 memory schema 作为证据接口，不是政策接口。** 建议的最小字段：`record_id`、`source`、`observed_at`、`valid_until`、`subject_scope`、`trajectory_id`、`policy_version`、`verification_status`、`supersedes`、`revocation_status`、`access_class`、`content_digest`。记录格式本身仍需团队审定；哈希只能帮助发现内容改动，不能证明观察真实或规则正当。
3. **有争议的状态留在可见审查队列。** 记忆检索可提示“有相似历史案件”，但不能把相似度分数当作授权。权限缺失、相互冲突或来源不明时，输出应是明确的 insufficient/review 路径，而不是从隐式状态补规则。
4. **评测门禁扩展到记忆特有风险。** 现有 G01–G10 已覆盖 schema、数据隔离、退化底线、条款覆盖、诚实声明与延迟披露。将来若加入记忆试验，可另增记忆血缘/过期条目/跨轨迹污染/删除或撤销生效等检查，但应当单独设计、红队验证和审查，不能以修改门禁适应候选系统。
5. **先跑记忆消融和简单基线。** 至少比较无记忆、可审计文本账本/检索、MEMT native memory 和 MEMT + 独立治理门；记忆写入规则、记忆容量、来源质量、遗忘/覆盖策略分别做消融。若不能访问可复现权重与合法数据，就先做接口抽象和合成场景，不暗示已复现论文模型。

## 7. 研究判断

MEMT-1.0 是**记忆系统研究**：它把线上经验状态纳入模型计算，展示了压缩历史与复用程序性经验的能力和代价。PoL2 公共品治理则至少还需要**共同体授权、资源规则、利益分布、争议解决和制度修订**。两者可通过“经核验的经验如何帮助治理执行”衔接，不能通过把 PoL2 变成模型记忆内容就宣称完成规范内化。

因此最值得做的下一步不是立即训练“记住 PoL2 的具身大模型”，而是用共享服务模拟把经验记忆与可审计治理状态接好，测出它是否改善服务，同时检查拒绝、撤权、少数群体可及、资源外部性和恢复状态。只有当记忆的净贡献可区分、公共福利条款已由团队决定、门控与恢复契约可审查时，才有依据讨论更深的 memory-native governance。
